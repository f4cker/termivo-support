Getting started

Amber requires iOS/iPadOS 26 or later. The app interface is Simplified Chinese. Personal mode needs no Amber account; bring your own authorized database server, network access and credentials. Amber does not provide hosted databases or database accounts. Team and gateway backends are not connected.

Supported targets are MySQL, PostgreSQL, single-node MongoDB, standalone Redis and a local SQLite file selected through Files. Compatibility with other products depends on their protocol and server features. MongoDB SRV/replica sets and Redis Cluster/Sentinel are not supported.

Connections, TLS and SSH

Check the host, port, username, database and network route. Local-network permission may be needed for LAN servers. TLS verifies certificates and hostnames by default. You can explicitly disable database TLS, including for PROD; connection failures never downgrade it automatically. SSH and SOCKS5 do not replace database TLS. Do not expose a database to the entire Internet to troubleshoot a connection.

Single/multiple SSH hops and authenticated SOCKS5 are supported separately; they cannot currently be combined. A saved jump host can be reused by other connections, and a CA imported for one connection can be chosen for another. SSH records the first host fingerprint and verifies later connections, blocking changes. Confirm the server identity before first use. HTTP CONNECT, automatic Wi-Fi proxies, SFTP and client TLS certificates are not connected. Supported PEM/DER CA roots can be imported from Files while retaining TLS/hostname checks; CA URL import is not available.

Import Ed25519, RSA or ECDSA P-256/P-384/P-521 private keys through the file picker or an explicit system paste action. Supported containers include OpenSSH, PEM and PKCS#8. An encrypted key needs a local unlock passphrase that is not saved. Credentials change only after successful import. SSH user certificates are supported separately from private keys; a missing synchronized certificate may leave ordinary public-key login available. Hardware keys, PuTTY PPK and DSA are not supported. Newly generated keys are Ed25519.

Queries, edits and operations

The SQL editor runs the selected or current statement, or every statement in order, as checked read-only queries with a result limit. Writes typed in the editor open a review, and several writes typed together can be reviewed as one transaction. Supported writes, imports, schema changes, migrations, routine calls and database administration use their own review and confirmation flows. Availability depends on the engine, object and account permissions. MySQL DDL implicitly commits and can partially succeed; PostgreSQL migrations use a transaction. MySQL procedures returning result sets are not supported.

Cancellation, timeout or disconnection does not prove a server-side write was undone. Verify unknown results on the target before retrying. PROD locking stops reads, previews and later batches; an already-sent write may finish. MySQL/PostgreSQL read cancellation attempts a bounded server-side stop and is best effort. A running read can be stopped from its result. On iPhone, closing the editor during a read asks whether to keep it running; on iPad, leaving the SQL workspace keeps it running. Opening that connection’s editor again shows the result. Supported MySQL reads use a server limit when available; MongoDB browsing uses bounded maxTimeMS.

Visible operations pages reuse their connection and release it when leaving, backgrounding or locking PROD. Polling backs off after failures and stops automatic refresh after authentication rejection. Background sampling has only a short system allowance and does not continue while suspended or terminated.

Query parameters use driver binding. Local history records the SQL template, not separate parameter input values; literals written directly in SQL can still contain business information. Recent tables and queries can reopen real local records. Folders organize saved queries. Charts, ER diagrams and date/time-zone display are processed on the device.

AI conversations and recovery

Configure your own HTTPS endpoint, model and API key in AI Service settings. OpenAI Chat Completions and Anthropic Messages compatible protocols are supported. Amber sends the AI API key to the configured endpoint as request authentication, including for explicit model-catalog requests; the key is not inserted into prompt or model context. When you send a request, Amber can include the question, matching conversation context, selected schema/comments, engine/time context, enabled global instructions and templates, Skill content the assistant requests on demand from your imported library, and files or images you selected for that request. SQL explanation or rewriting sends the current SQL. Configured database, SSH and proxy credentials are not included in model context. Provider fees and retention follow the provider’s policies.

ASK can inspect metadata and generate or explain queries without reading business records, Redis key names or key values. Agent data tasks require the on-device read-only sharing consent. Read-only analysis is optional. After the on-device sharing disclosure is acknowledged and you send a question, the model can work within the databases you selected on the same saved connection. Depending on the engine, it can request checked SQL reads and ordinary EXPLAIN, bounded MongoDB reads, Redis server metadata and bounded key scans or value reads, and bounded vector collection and payload reads. Observations can include database, table, collection and field names, Redis key names and limited key metadata, vector collection names and payload fields, indexes/foreign keys, engine version, device time/time zone, bounded result previews and normalized plans. There is no fixed per-turn SQL or tool-call count cap. Each operation retains timeout and engine-specific result budgets; SQL results are bounded to 50 rows, 40 columns, 512 characters per value and about 12 KB of encoded context, with further trimming possible. Repeated calls without new evidence stop. Attachments can be text, CSV, Excel (.xlsx, one CSV per visible sheet), PDF, Word (.docx) or images; Excel, PDF and Word are converted to text and image or scanned-page text is recognized on the device. Encrypted files and legacy .xls/.doc are not supported. Analysis can read whole text attachments on the device, use an attachment column as a list of values in a checked read, save complete read results into a per-conversation on-device workspace (up to 200,000 rows; PROD asks once per session first), query it locally and export CSV, JSON or Excel files. The model receives only bounded previews. Workspaces are removed after 7 days without use by default; AI customization can instead remove them when you leave the conversation or keep them until you delete them. Names, keys, payloads and result previews can contain business information. Review sensitivity before sharing. Credentials, raw server errors, raw plans and embedding vectors are not automatic observations. No write, arbitrary-command or connection-switch tools are exposed.

Global instructions and enabled templates apply only to AI requests. Imported Skills are stored as user-controlled reference material and are read only when selected or requested; Amber does not execute Skill scripts, and Skill text cannot grant database access or bypass the current connection, database, lock or read-only limits. The customization file and app-owned Skill library use complete file protection and are explicitly excluded from system backup.

Text and SQL stream as previews; Send changes to Stop during a request. Partial SQL cannot execute. Tools and final SQL require a complete successful response and validation. Analysis SQL with an attached result starts collapsed. Local history remembers mode preferences, never execution grants. Runtime connection, service and lock checks still apply; historical content from another scope is display-only.

Conversation history, attachment references and interrupted questions, received text and read-only tool progress with bounded results are saved locally with data protection for recovery. Conversation history and recovery records are explicitly excluded from system backup. Separate attachment copies and persistent queue records use complete file protection but are not universally marked as excluded from system device backups. These records are not sent through Amber’s optional iCloud sync features; whether device backups include a file also depends on system backup settings and that file or directory’s resource flags. Amber does not automatically add AI API keys or raw execution errors to these records. Completed or cancelled queue entries remain until you clear finished tasks; a failed or interrupted task pauses and can be continued. Attachment copies are retained while referenced by a draft, active session, conversation history, recovery state or queued task, and cleanup removes them only after all such references are gone. After a disconnect, return to the conversation and choose Continue; after restarting, reopen the conversation from local history or task queue.

Continue can send a new request to the matching original AI service with the question, saved text and necessary tool context. Matching steps whose successful results were saved reuse those results and their original capture time; incomplete reads are revalidated before retry. Unknown outcomes cannot be promised exactly once. Changing the connection configuration or AI service invalidates old recovery progress. Completion removes temporary checkpoints; values included in an AI answer may remain in ordinary history. Local conversations can be deleted from history.

A request, queued task or editor query that is still running after a moment may continue as an iOS system background task with generic progress on the Lock Screen; a step that needs your confirmation pauses until you return. Otherwise it may continue or recover during the short background allowance granted by iOS. Expiry, locking or loss of connection may pause it; return to the foreground to continue or retry. An analysis iOS paused can continue by itself when you return and unlock within 15 minutes; one you stopped does not. Continuous background execution is not guaranteed. Recovery has passed four physical iPhone cases using a controlled HTTPS model and real SQLite, plus 102 targeted simulator regressions. This does not verify every external AI service, production database, TestFlight upgrade or full device performance.

Voice input

The in-app microphone uses Apple Speech for on-device transcription after microphone permission. System language assets may need downloading; support depends on device and locale. Audio stays in memory, with no recording file or provider upload. Interim text is a preview. Cancel preserves the original draft; Finish appends final text to an editable draft. Only manual Send shares that text through the AI flow. Leaving, backgrounding, locking, changing conversations/services or opening an overlay cancels voice input. The voice-start callback crash is fixed; real speech quality, Bluetooth and call interruptions remain to be verified.

iCloud and credentials

Connection-profile sync uses Apple iCloud KVS after account verification. Existing profiles require first-time confirmation under My → iCloud Sync. It can sync names, hosts, ports, usernames, database options, stable UUIDs and non-credential SSH/proxy metadata, including supported public CA DER in V2 profiles. Passwords, private keys, local SSH fingerprints, SQLite files/bookmarks, query content/results and AI keys are excluded from profile sync. Received profiles do not automatically connect; new or restored targets require credential confirmation. Offline changes wait and conflicts retain both versions.

Database passwords, supported SSH credentials and user certificates use separate Keychain items governed by their sync controls and system iCloud Keychain settings; proxy passwords remain local. Import passphrases are not saved. Migration failures retain usable local credentials and report the issue. The app cannot prove another device has received an item.

Saved queries and query history have separate, initially disabled private CloudKit sync switches. SQL, titles and connection names use encrypted fields; UUIDs, timestamps, durations, row counts and failure flags are ordinary metadata. Result rows and editor drafts are excluded. Settings sync uses a whitelist including appearance/editor/notification preferences, AI protocol/HTTPS endpoint/model and row-card/table display. Received AI settings require local confirmation before requests. Folder KVS sync is separate and contains folder names, saved-query UUID membership, revisions and deletion markers, not SQL.

AI-key sync is separate, initially disabled and controls sending/receiving through system iCloud Keychain, independently of database/SSH switches. Disabling attempts to preserve a usable local copy before removing matching cloud data; errors retain data and report failure. Keys are isolated by endpoint/protocol and are absent from configuration files, history and logs. Settings and folder sync bind and verify the Apple account; account changes pause them until explicitly enabled. Disabling sync does not automatically erase submitted records. Lock/privacy/PROD-verification settings stay per device. Real two-device delivery, account changes and deletion propagation remain unverified.

Files, sharing and feedback

Choose import files and verify parsing, column mapping, destination and review information before writing. SQLite uses selected files, working copies and explicit save checks; failures may leave recovery files with a notice. Export/share can produce CSV, JSON, SQL, Excel or images, including selected headers/comments and database content. Amber does not automatically encrypt or redact those files. Masking rules are local drafts/previews. You control destinations and recipients.

Static HTML preview/export is generated on the device from the content you select and opened as a local preview before you choose whether to save or share it. The HTML can contain query text, schema, result values or AI-produced explanations. Review it before exporting; Amber does not upload the preview to a developer-hosted site.

Copied results enter the system clipboard with an optional expiry; this does not erase copies already pasted, exported or retained by another app. Non-PROD system Handoff can share bounded SQL or object names to your Apple devices and can be disabled in settings; receipt does not execute SQL. Saved-query Shortcuts retain their read-only and device-verification limits. Actual cross-device Handoff/certificate delivery and Shortcuts acceptance remain unverified.

Help and Feedback is available under My / General. It does not send a report automatically. TestFlight installation, diagnostics and feedback are provided by Apple under its policies and your settings. Current testing is limited to the original internal account, with no France distribution, public/external beta or App Store submission.

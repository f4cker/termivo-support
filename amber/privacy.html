支持 / Support隐私 / Privacy

更新日期 / Updated: 2026-10-15

本政策说明 LAVAS LABS LIMITED 提供的 Amber 如何处理信息。隐私问题请联系 reallayoute@gmail.com。本政策适用于 0.1.0 (2) 及其后的当前个人测试版本；构建 1 的数据库密码仅存本机，且没有接通 AI 服务。

本机配置、查询与凭据

连接名称、主机、端口、用户名、数据库名称及连接选项保存在应用的本机存储中。数据库密码使用系统钥匙串保存，配置文件不包含密码。0.1.0 (2) 起，数据库密码使用允许同步的钥匙串属性，系统可按你的 Apple 账户及 iCloud 钥匙串设置在兼容设备间同步。旧本机密码会尝试迁移；迁移失败或冲突时会保留可用密码并提示。App 无法确认跨设备送达进度。0.1.0 (4) 起，SSH 密码与支持格式的私钥也使用允许同步的独立系统钥匙串服务；代理密码及 AI API 密钥保存在独立的仅此设备钥匙串，不参与同步。0.1.0 (6) 起，SSH 跳板与代理配置中的非凭据元数据可随连接配置同步；已信任 SSH 主机指纹仍仅在本机。SSH 密钥管理页仅在你明确操作时复制或分享公钥，私钥保留在系统钥匙串，公钥副本由你和接收者管理。0.1.0 (5) 起，你可通过系统文件选择器授权读取私钥文件，或主动使用系统粘贴按钮导入私钥内容。加密私钥的口令仅在设备上用于解锁，不保存或上传；只有导入成功才替换凭据。归一化后的私钥沿用允许系统钥匙串同步的保存方式，App 不提供跨设备送达确认。原始文件、剪贴板和已粘贴副本由你及对应存储服务管理。收藏查询、SQL 历史和草稿存于本机，可能包含你输入的业务信息或 SQL 字面值；查询库文件标记为不参与系统备份。

0.1.0 (6) 起，在验证当前 iCloud 账户并启用连接配置同步后，个人网络连接名称、主机、端口、用户名、数据库选项、稳定 UUID、SSH/代理非凭据元数据，以及版本和删除标记由 Apple iCloud KVS 同步。地址和用户名可能含敏感信息，请在开启前核对。升级已有配置后须在“我的 → iCloud 同步”首次确认开启；空的新设备经账户验证后可接收。连接配置同步借助 CloudKit 获取容器内匿名账户标识，摘要只在本机；连接配置由 KVS 处理。新版查询库记录另按下述独立功能处理。账户未验证时不上传；切换账户暂停同步，需你重新明确开启。关闭同步不会自动删除已提交到 Apple iCloud 的配置。离线修改保留待同步，冲突保留双方供选择；同步删除只处理连接配置，不删除数据库服务器记录。密码、私钥、SSH 主机指纹、SQLite 文件和书签、查询库、结果、缓存及 AI 密钥不进入配置同步；密码和 SSH 凭据仍由系统 iCloud 钥匙串单独处理。页面本机提交/接收状态不能证明另一设备已收到。并非所有本机文件都被排除于系统备份；设备备份、系统钥匙串及 Apple 服务遵循你的系统设置与 Apple 政策。卸载应用不保证钥匙串条目、系统备份或你自行保存的文件同时删除。

你选择连接的数据库

Amber 根据你的操作向你指定的数据库服务器传输认证信息、查询或已确认的变更、导入数据及必要的协议与网络数据，并接收结构信息、查询结果和服务器状态。远程查询结果会在设备上处理和展示。Amber 不把这些数据库凭据、查询或结果主动上传到开发者的数据库服务。

数据库运营者及其网络服务可能记录连接、查询和相关活动，并按其政策保留数据。请仅连接你信任且获授权使用的数据库，并按需要启用 TLS 和最小权限账号。TLS 默认完全校验；你可明确选择关闭 TLS，包括 PROD 连接，这会取消数据库协议本身的 TLS 保护，应用不会因连接失败自动降级。SSH 与 SOCKS5 是网络路径选项，不代替数据库 TLS。

SSH 隧道、代理与主动复制

0.1.0 (4) 起可按你的操作通过 SSH 单跳/多跳隧道，或 SOCKS5 代理访问你指定的数据库。SSH 服务器接收逐跳认证与转发目标，代理接收认证信息和连接目标；这些服务器及网络运营者可能记录连接活动。新版首次 SSH 连接自动记录主机指纹，之后自动核对，变更会阻断；首次连接前由你确认目标服务器身份。SSH 与 SOCKS5 当前不能组合使用；HTTP CONNECT、Wi-Fi 自动代理与 SFTP 文件获取尚未接入。

你主动复制查询结果时，内容进入系统剪贴板，可按应用设置附带到期时间，由系统处理；系统连续互通与接收应用遵循你的系统设置及其政策。到期不删除已经粘贴、导出或被其他应用保存的副本。结果导出支持 CSV/JSON，脱敏规则当前只是本机草稿与预览，不自动脱敏复制或导出的真实记录。

文件导入、导出与本地数据库

你通过系统文件选择器授权 Amber 读取所选文件。应用会解析导入数据，按你的明确操作向目标数据库发送数据；本地 SQLite 文件会被读取并按功能需要制作工作副本。文件操作可能产生临时文件，写回失败等情况可能保留恢复用备份，并在界面提示。文件位置可能由你选择的云端文件提供者管理。

导出或分享的 CSV、JSON、SQL 等文件可能包含数据库记录、结构或查询内容，Amber 不自动对这些数据文件加密。选择保存位置、共享服务、接收者和删除导出文件由你决定；文件提供者或接收者可能按自己的政策保存副本。

系统权限与设备保护

本地网络权限用于连接局域网数据库。启用应用锁时，系统进行面容 ID 或设备密码验证，Amber 不接收或保存你的面容生物特征数据或设备密码。相机权限仅用于你主动进入的二维码扫描，图像在设备上处理，不用于拍照、保存或上传。通知权限用于应用中已提供的本机通知与测试通知；当前没有接入团队远程推送服务。

应用读取自己的偏好设置以提供外观、锁定与导航设置；按文件功能读取用户选择文件的元数据以检查变化，并在文件写入前检查可用磁盘空间。这些信息用于本机功能，不用于设备指纹识别或广告跟踪。

你选择的 AI 服务

AI 功能默认未配置，只有你填写自己的 HTTPS 服务地址、模型和 API 密钥并主动发送问题时，Amber 才会请求该服务。请求使用该服务的 API 密钥进行认证，并包含问题文本、数据库引擎、所选表名和表结构。0.1.0 (3) 起，连续追问还会发送当前对话中已成功完成的问题、回答与生成 SQL；更换服务配置或数据库引擎会清空对话历史。你主动使用 SQL 解释或改写时，会发送当前 SQL 文本、任务说明和数据库引擎，SQL 可能包含业务信息或字面值。生成 SQL 模式不自动附带数据库查询结果行或数据库登录密码；主动授权的只读分析模式会按下文分享受限结果预览。但你输入的问题、历史内容或 SQL 可能包含敏感内容，请核对后发送。查询结果图表在设备上生成，不因绘图上传结果。0.1.0 (4) 起，主动请求运维 AI 诊断时会发送选中慢语句/会话的引擎、采样时间、指标、采样限制、规范化执行计划摘要和经过字面值/注释处理的 SQL；不自动附带原始计划、服务器错误、连接凭据或结果行。SQL 标识符与指标仍可能包含业务信息，请核对后请求。服务返回的回答和建议 SQL 会在设备上展示，生成 SQL 模式的候选不会因收到回答而自动执行；改写结果需你明确应用至编辑器，再按正常只读查询流程手动运行。

API 地址和模型名称保存在本机偏好设置中；API 密钥按服务地址分别保存在专用本机钥匙串中，不进入连接配置、查询库、日志或 iCloud 钥匙串。请求不使用持久化 HTTP 缓存或 Cookie，也不跟随 HTTP 重定向转发请求。你可以在 AI 服务设置中移除当前服务的密钥，未配置时无法发送 AI 请求。所选服务提供者可能处理和保留问题、对话历史、SQL、表结构与回答；请在配置前查看其隐私政策、费用和数据保留规则。

团队、统计与广告

当前没有接入团队账号后端或团队网关。当前版本不包含广告、不进行跨应用广告跟踪，也不主动向开发者的统计服务发送使用数据。未来接入新的服务前，会更新本政策并说明相关数据流。

支持、TestFlight 与 Apple 服务

你主动发送支持邮件或反馈时，我们会使用你提供的邮箱、问题说明、截图和日志处理请求。请只提供必要且已脱敏的信息，不要发送密码、连接串、服务器地址或生产数据。支持信息在处理请求所需期间保留；可通过上述邮箱提出访问、更正或删除请求，适用法律或必要记录保存要求除外。

TestFlight 的安装、使用诊断、崩溃信息和 Beta 反馈由 Apple 根据你的设置及其政策处理，Apple 可能向开发者提供测试反馈和诊断信息。系统邮件、文件共享、备份等外部服务也按各自政策处理数据。当前测试版本没有应用内购买或订阅功能。

你的控制与删除

你可以在 Amber 删除连接及对应凭据、删除查询收藏或清除查询历史；也可在 AI 服务设置中移除当前服务密钥，或在系统设置中撤销已授予的权限。同步密码的删除和保留受系统 iCloud 钥匙串处理；App 不删除数据库服务器或 AI 提供者已经保存的数据。临时文件、文件备份及导出文件的保留取决于具体功能和保存位置，系统备份和钥匙串可能有独立的保留机制。数据库服务器上的记录需要通过数据库运营者或授权管理流程处理，删除本机连接不会删除服务器上的数据。

政策变更

数据处理方式变化时，我们会更新本页面和日期。隐私问题及请求请联系上述支持邮箱。

Privacy Policy

Amber is provided by LAVAS LABS LIMITED. Updated October 15, 2026. Contact: reallayoute@gmail.com. This policy applies to the current personal beta from 0.1.0 (2). Build 1 used device-only database credentials and had no connected AI service.

Local data and credentials

Connection settings, including database hosts and usernames, are stored on your device. Database passwords are not stored in connection configuration files. From 0.1.0 (2), they use synchronizable Keychain attributes; system iCloud Keychain may sync them across compatible devices according to your Apple account and settings. Legacy device-only items are migrated when possible; usable local passwords are retained on migration failures or conflicts. Amber cannot confirm delivery to another device. From 0.1.0 (4), SSH passwords and supported private keys also use a separate synchronizable system Keychain service. Proxy passwords and AI API keys remain in separate device-only Keychain services. From 0.1.0 (6), non-credential SSH hop and proxy metadata can sync with connection profiles; accepted SSH host fingerprints remain local. The SSH key management page explicitly copies or shares public keys only; private keys remain in the system Keychain. Public-key copies are managed by you and their recipients. From 0.1.0 (5), you may select a private-key file or explicitly use the system paste button to import its contents. An encrypted-key passphrase is used locally to unlock the key; it is not saved or uploaded. Existing credentials change only on successful import. The normalized private key uses the existing synchronizable Keychain service, without delivery confirmation from Amber. You and the relevant storage providers manage the original file, clipboard and pasted copies. Saved SQL, history and drafts may contain business information or literal values; query-library files are excluded from system backup. From 0.1.0 (6), after account verification and enabling connection sync, Apple iCloud KVS synchronizes personal network profile names, hosts, ports, usernames, database options, stable UUIDs, non-credential SSH/proxy metadata, versions and deletion markers. Hosts and usernames may contain sensitive information; review them before enabling. Existing profiles require first-time confirmation in My → iCloud Sync; empty new devices can receive after account verification. Connection-profile account verification obtains a container-scoped anonymous CloudKit identifier; its digest stays local and profile data travels through KVS. New query-library records are handled separately as described below. Unverified accounts do not upload; account changes pause sync until explicitly re-enabled. Disabling sync does not automatically erase profiles already submitted to Apple iCloud. Offline changes wait for sync and conflicts retain both versions; profile deletion does not delete database-server records. Passwords, private keys, SSH fingerprints, SQLite files/bookmarks, query history, results, caches and AI keys are excluded from profile sync. System iCloud Keychain handles credential synchronization separately. Local submit/receive status does not prove delivery to another device. Other files, Keychain items and system backups may follow separate retention rules; uninstalling the app does not guarantee their deletion.

Databases and files you choose

Your actions send authentication information, queries, confirmed changes, import data and protocol data directly to the database servers you select. Results and schema information are processed and displayed on your device. Amber does not proactively upload this database content or credentials to a developer-hosted database service. Server and network operators may log activity. Use trusted, authorized databases, TLS and least-privilege accounts. Full TLS verification is the default; explicitly selecting disabled TLS, including for PROD profiles, removes database-protocol TLS protection. Connection failures never automatically downgrade TLS.

Selected files are accessed through system-granted file permissions. Imports may send selected data to the target database after your confirmation. Local SQLite operations may create working copies; temporary or recovery files may be retained when an operation fails. Exported or shared CSV, JSON and SQL files may contain database content and are not automatically encrypted by Amber. You control their destinations and recipients; cloud file providers and recipients follow their own policies.

SSH, proxies and copied results

From 0.1.0 (4), your actions can use single/multi-hop SSH tunnels or SOCKS5 proxies. SSH servers receive hop authentication and forwarding targets; proxies receive authentication and destination metadata. Those operators may log connections. New builds automatically record first-use SSH fingerprints and verify subsequent connections; changes block access. Confirm the target identity before first use. SSH and SOCKS5 cannot currently be combined; HTTP CONNECT, automatic Wi-Fi proxy selection and SFTP downloads are not connected. These routes do not replace database TLS.

Explicitly copying query results places content in the system clipboard with an optional expiration handled by the system. Continuity and receiving apps follow system settings and their policies. Expiration does not remove content already pasted, exported or saved elsewhere. CSV/JSON result exports are not automatically encrypted or masked. Masking rules currently provide only local drafts and supplied-value previews.

Permissions and services

Local-network permission supports LAN connections. App lock uses system Face ID or device-passcode verification; Amber does not receive biometric templates or the device passcode. Camera access is for on-device QR scanning, not saving or uploading photos. Notification permission supports currently available local/test notifications. Preferences, selected-file metadata and free disk space are accessed for app settings and file operations, not fingerprinting.

AI services you configure

AI is unconfigured by default. After you supply your own HTTPS API endpoint, model and API key and send a question, Amber authenticates to that provider with its key and sends your question, database engine, selected table names and schema. From 0.1.0 (3), follow-up requests also include completed questions, replies and generated SQL from the current conversation; changing the service configuration or database engine clears that history. When you request SQL explanation or rewriting, the current SQL text, task instructions and database engine are sent to the provider. Questions, history and SQL literals may contain sensitive content. In SQL-generation mode, database result rows and login credentials are not automatically included. Explicitly authorized read-only analysis can send bounded result previews as described below. Result charts are generated on-device without uploading rows for charting. From 0.1.0 (4), an explicit operations-AI diagnosis sends selected slow-statement/session facts: engine, sample time, metrics and collection limitations, normalized plan summaries and SQL after literal/comment redaction. Raw plans, remote errors, connection credentials and result rows are not automatically attached. Identifiers and metrics may still contain business information; review the context before requesting diagnosis. Replies and suggested SQL are shown locally; rewrites require your explicit application to the editor, and SQL-generation candidates are not automatically executed.

Endpoint/model settings stay in local preferences. API keys are stored separately for each endpoint in a device-only Keychain service, not in connection files, query history, logs or iCloud Keychain. Requests use no persistent HTTP cache or cookies and are not forwarded through HTTP redirects. Remove the current service key in AI settings to disable its requests. The provider may process and retain prompts, conversation history, SQL, schema and responses; review its privacy, retention and pricing policies before configuring it.

The current version has no team backend or gateway, no query-result cloud sync, no advertising, no cross-app tracking and no proactive developer analytics uploads. It has no in-app purchases or subscriptions. We will update this policy before connecting new services.

Support, Apple and your choices

If you contact support, we use the email, description and redacted attachments you provide to handle your request. Keep credentials and production data out of reports. Information is retained as needed for support and applicable record-keeping; contact us to request access, correction or deletion. Apple processes TestFlight installation, diagnostics, crashes and beta feedback under its policies and your settings, and may share reports with developers. Other services, including email, backup and sharing providers, apply their own policies.

You can delete local connections and associated credentials, remove saved queries or clear query history, remove the current AI service key, and revoke system permissions. System iCloud Keychain manages deletion/retention of syncable passwords. Amber does not delete information already held by a database or AI provider. Files, backups and Keychain items may have separate retention. Deleting a local connection does not delete database-server data. Contact the support address above for privacy questions.

新版查询收藏、历史与偏好同步

0.1.0 (7) 起，收藏与历史分别由你开启后写入当前 Apple 账户的私有 CloudKit 数据库，初始默认关闭。SQL、收藏标题及连接显示名称使用 CloudKit 加密字段；连接 UUID、日期、运行次数、耗时、行数和失败状态使用普通字段。SQL/标题/名称可能含业务信息，启用前请核对。查询结果行、编辑草稿、密码、私钥和本机 SSH 指纹不进入此功能。锁定与隐私设置保持本机，外观、编辑器、通知等白名单偏好可另经 Apple iCloud KVS 同步。首次设置同步在云端内容未确认时等待，明确使用本机设置可能替换云端快照。账户切换关闭新增同步开关。关闭同步不自动删除已有云记录；再次开启会对账已知删除意图和本机编辑，冲突中的编辑可能保留。系统 iCloud、钥匙串加密材料与 Apple 服务遵循你的账户设置及 Apple 政策；页面本机状态不是另一设备送达确认。

新版 CA 文件导入处理你选择的 PEM/DER CA 证书，拒绝将私钥作为 CA 内容。受支持的公共 CA DER 可随 V2 连接配置同步；证书中的组织等元数据可能包含业务信息，请开启配置同步前核对。本机通知采用通用内容，不将 SQL、结果或连接名称放到锁屏通知中。后台采样只有短暂系统预算，挂起/退出后不持续运行。收藏/历史/设置和 CA V2 的真实双设备送达尚待验证。

New library and preference sync

From 0.1.0 (7), saved queries and history have separate, initially disabled switches. Once enabled and account-verified, they write to your Apple account's private CloudKit database. SQL, saved titles and connection display names use encrypted fields; connection UUIDs, dates, counts, duration and failure flags use ordinary fields. Review business information before enabling. Result rows, drafts, passwords, private keys and local SSH fingerprints are excluded. Whitelisted appearance/editor/notification preferences can separately use Apple iCloud KVS; lock/privacy settings stay local. Unknown initial cloud preferences wait for explicit confirmation, and choosing local settings can replace the cloud snapshot. Account changes disable these new switches. Turning them off does not erase existing records; enabling again reconciles known deletion intent and edits, and conflicts may retain edits. Apple iCloud/Keychain retention and encrypted-key access follow your account settings and Apple's policies. Supported public CA DER from selected PEM/DER files may use V2 profile sync without private keys or source paths; certificate metadata may contain business information. Local notifications use generic text and background sampling has a short system budget. Real new two-device delivery is not yet verified.

0.1.0 (9) 的参数与最近记录

查询参数值通过数据库驱动发送到你选择的数据库；本机查询历史记录 SQL 模板，不记录这些独立输入的参数值。SQL 本身仍可能含你直接写入的业务字面值。最近表和查询入口的连接及对象元数据保存在本机；它不代表跨设备接力已送达。结构变更和运维写入仅在你确认后发送到所选数据库，服务器按其账号权限和保留政策处理。帮助页不自动发送反馈；通过 TestFlight 或邮件主动反馈时仍按上述 Apple 服务与支持说明处理。

Parameters and recent items in 0.1.0 (9)

Parameter values are sent through the database driver to your selected database. Query history records the SQL template rather than these separate parameter inputs; literals written directly into SQL can still contain business information. Recent connection and object metadata is stored locally and does not confirm cross-device delivery. Confirmed schema and operations writes are sent to the selected database under its permissions and retention policies. Local help does not automatically send feedback; TestFlight or email feedback remains subject to the Apple and support terms described above.

0.1.0 (11) 的本机历史、接力与管理操作

AI 问数历史（问题、回复、生成 SQL 和连接标识）可保存到应用本机受系统文件保护的文件，排除系统备份；不自动加入查询库 CloudKit 同步。恢复的对话在你继续提问时会按当前 AI 服务协议发送。主动获取模型列表会向你配置的 HTTPS 服务发送对应 API Key；Anthropic 兼容请求发送到该服务的 messages 接口，业务信息发送范围沿用上述问数/解释/运维规则。

系统接力在本机默认开启，可在设置中关闭；仅未锁定的非 PROD SQL/表活动可提供给本人 Apple 设备。活动包含连接 UUID、SQL（最多 3 KiB）或库/表对象名称，不包含主机地址、登录凭据或结果行。SQL 与对象名仍可能包含业务信息，请按需要关闭接力。接收后不会自动执行 SQL。收藏查询快捷指令需遵循其只读及设备验证限制。

SSH 用户证书与私钥作为独立钥匙串项保存，随对应凭据同步开关处理。证书是公有认证材料，仍可能包含账号、principal 或组织标识；启用前核对。查询文件夹保存在本机，主动分享 SQL、导出 Excel/图片及表头时会将选中的内容交给系统文件/分享目标；应用不能撤销其他应用保存的副本。

数据、账号、权限及参数等管理操作在明确确认后把必要值（包括你输入的新数据库口令）发送给选定数据库，不自动发给 Amber 或 AI。锁定不会撤销已经发出的服务器写入；具体结果、日志与保留由数据库负责。真实跨设备送达和 Handoff/快捷指令仍待验证；AI 当前仅有 Anthropic 合成样本证据。

History, Handoff and management in 0.1.0 (11)

AI questions/replies/generated SQL and connection identifiers can be stored in a system-protected local history file excluded from backup, outside query-library CloudKit sync. Continuing a restored conversation sends its context to your configured provider. Explicit model discovery sends that provider your API key over HTTPS; Anthropic-compatible exchanges use its messages endpoint. Non-PROD Handoff is initially on and can be disabled; while unlocked it shares a connection UUID and bounded SQL or object names through Apple's Handoff, without hosts, credentials or rows. SQL/object names can contain business information; receipt does not execute SQL. SSH certificates are separate Keychain items governed by credential sync and can contain principals/organization metadata. Explicit sharing/export hands selected content to the system destination. Confirmed database administration sends required values, including entered new database passwords, to the chosen database, not automatically to Amber or AI. Locking/timeout cannot retract already-sent writes. Real devices and cross-device delivery remain unverified; live AI evidence is limited to synthetic Anthropic fixtures.

0.1.0 (12)：AI 只读分析与查询性能

AI 默认保持生成 SQL 模式，由你明确运行。新版可在当前连接主动授权只读分析；启用后，模型可列出表、读取结构、执行受检单条 SELECT 和普通 EXPLAIN，并向你配置的 HTTPS AI 服务发送工具观察，包括表/列名称与注释、索引/外键、数据库版本、设备时间与时区、受限结果预览和计划摘要。每轮最多 6 次工具调用、其中最多 3 次查询；每次结果最多 50 行、40 列、每值最多 512 字符，编码预算约 12 KB，内容可能进一步裁剪。预览仍可能包含敏感业务信息，请仅在确认可分享时启用。登录凭据、原始计划和原始服务器错误不自动作为工具观察发送；问数历史保存在本机，继续对话会发送本轮上下文。授权随当前连接/服务作用域核对，锁定、切换或取消会中断后续步骤。模型不执行写入、切换数据库或任意系统命令。

运维页面可见时按连接复用链路，离页、后台或锁定 PROD 时释放；失败轮询退避，认证拒绝停止自动刷新。MySQL 编辑器在识别支持的服务器时采用默认服务端上限，Mongo 浏览带有界 maxTimeMS；取消或客户端超时时尝试终止对应 MySQL/PG 读取，失败可能仍有服务器工作，不能据此判定写入已撤销。查询默认行数可选 10–1000，改进大结果表格、CSV 行数检查和 iCloud 首次查询库合并。修复小样本 AI 图表与输入区交互。当前未做本版实际 TestFlight 升级、跨设备同步或完整真机性能/耗电验收。

0.1.0 (12): opt-in read-only AI analysis

SQL generation remains the default and requires you to run the candidate. After explicit authorization for the current connection, read-only analysis can list tables, describe schema, run checked single SELECT statements and ordinary EXPLAIN, then send tool observations to your configured HTTPS AI provider. Observations include bounded schema/comments/indexes/foreign keys, engine version, device time/time zone, result previews and plan summaries. A turn allows at most six tools and three queries; a result is capped at 50 rows, 40 columns, 512 characters per value and about 12 KB of encoded context, with possible further truncation. Previews may still contain sensitive business data. Database credentials, raw plans and raw server errors are not automatically attached as tool observations. Current local conversation context is sent on follow-up. Connection/service scope and lock state are rechecked; switching, locking or cancellation stops later steps. No writes, database switching or arbitrary system commands are exposed. Visible operations pages reuse connections and release them when leaving, backgrounding or locking PROD. Poll failures back off; rejected authentication stops automatic polling. Read cancellation/timeout attempts a bounded server-side stop for MySQL/PostgreSQL; it is best effort and does not undo writes. Physical TestFlight upgrades, cross-device sync and complete device energy/performance validation remain outstanding.
